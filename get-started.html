spiDE

spiDE finds neighbourhood-dependent differential expression in spatial transcriptomics. Cells of one type do not behave the same everywhere in a tissue. A tumour cell sitting among fibroblasts may express a different set of genes from a tumour cell surrounded by other tumour cells, and the way it responds may differ between patients who respond to a treatment and patients who do not. spiDE asks, for a chosen index cell type, whether the expression of a gene changes with the local density of another cell type, which we call the niche, and whether that change differs between two conditions.

Doing this well is harder than it sounds. The cells of one patient share their genetics, their treatment and the way their sample was handled, and neighbouring cells share their local tissue environment. If every cell is treated as an independent observation, the more cells are measured the more certain a result looks, even when the patients disagree with each other. A condition such as response to treatment is a property of a patient, not of a cell, so the patient is the right unit of replication. spiDE builds this into every test: the evidence for a result is how consistently the niche slope behaves between patients, never how many cells were measured.

One hypothesis is one (gene, index type, niche type) combination, which we call a triplet. Each triplet gets up to two tests:

  1. The pooled test asks whether, within patients, the gene’s expression in the index type changes with the density of the niche type, consistently across patients.
  2. The condition-specific test asks whether that dependence differs between two conditions, such as responders and non-responders.

Both tests look at slopes within patients. A condition that only shifts a gene’s overall level, or only changes how much of a cell type patients have, is not tested here; those are questions for pseudobulk differential expression and composition analysis. The analysis runs in three steps, and each has its own function:

  1. Build the niches (buildNiches() in R, build_niches() in Python) measures the density of every cell type around every cell.
  2. Fit (fitSpiDE() in R, fit_spide() in Python) fits a negative binomial regression for every gene in every index type, with a separate baseline for every patient, so that the niche coefficients are slopes within patients.
  3. Test (testSpiDE() in R, test_spide() in Python) tests those slopes across patients.

spiDE() in R and spide() in Python run all three in one call.

This website documents two packages that implement the same method: the R package spiDE and the Python package spidepy. Every step below is shown in both. Pick a language in any tab and all the tabs on the site follow. The example is the small simulated data set that ships with both packages, so nothing is subsampled or simplified to keep the page quick: the whole page runs in about a minute. The two packages are separate implementations of one method, so we should not expect identical output in general. On this data set the tables agree to numerical precision, which we check directly near the end of the page; on other data they agree qualitatively, with small numerical differences, and R vs Python lists where the two packages intentionally differ. The statistics are explained in The spiDE model, how well the tests hold up in Validation, and how many patients and cells a study needs in Designing a study.

Load the data

We begin by loading a small simulated data set that ships with the package. It holds 16 patients, eight responders and eight non-responders, with 150 cells each, three cell types (A, B and C) and 20 genes. We planted exactly one effect in it: gene G1 is up-regulated in index type A, in responders only, in proportion to the local density of niche type B. Because we know the answer, we can check that spiDE finds it. The Python package ships the same data.

The same 2,400 cells and 20 genes are loaded in both. The two conditions have eight patients each, and the three cell types are present in similar numbers. spiDE needs the following in the object:

  • Raw integer counts: the counts assay in R, layers["counts"] in Python (assay= names another layer, and "X" uses adata.X). Normalised or back-transformed values are refused, because the model needs the counting noise of real counts.
  • A cell type for every cell, in cell_type.
  • A patient for every cell, in sample_id. There should be one sample per patient. If a patient has several sections, put the patient in sample_id and the section in section, so that spatial variation is estimated for each section separately.
  • The spatial coordinates, in spatialCoords() in R and obsm["spatial"] in Python.
  • For the condition-specific test, a two-level condition that is constant within each patient, here the condition column. If the condition is partly confounded with slide or batch, a patient-level column of slides can be given as strata.

The container is a SpatialExperiment in R and an AnnData in Python.

Build the niches

For each cell, buildNiches() places a smooth bump, a Gaussian kernel, on every cell of a given type and adds the bumps up. The result is a density of each cell type at every cell, which says how much of that type there is nearby. The width of the bump, sigma, is the bandwidth and is in the units of the spatial coordinates. Each density is stored as a column of a reducedDim named after the bandwidth in R, and in obsm["Niche30"] in Python, which build_niches() fills in place unless copy=True.

  • Python

Choose a bandwidth

The bandwidth sets what we mean by a neighbourhood. A small bandwidth looks at the immediate neighbours of a cell, and a large one at the tissue around it. A good bandwidth gives a niche map that is neither speckled nor flat. We can look at the density of niche type B in one sample at two bandwidths and judge by eye. In Python, copy=True leaves adata with the bandwidth 30 only.

  • R
  • Python
spe2 <- buildNiches(spe, sigma = 10, verbose = FALSE)
plotNicheMap(spe2, niche = "B", sample = "S1", index = "A", sigma = 10)
plotNicheMap(spe2, niche = "B", sample = "S1", index = "A", sigma = 30)
adata10 = sp.build_niches(adata, sigma=10, copy=True)
fig = sp.pl.plot_niche_map(adata10, niche="B", sample="S1", index="A", sigma=10)
plt.show()
fig = sp.pl.plot_niche_map(adata10, niche="B", sample="S1", index="A", sigma=30)
plt.show()

At the smaller bandwidth most cells have no niche cell of type B within reach and the density is zero, so the map is speckled by the position of single cells. At the larger one the density varies smoothly across the section, and we can see where B cells are concentrated. We use 30 for the rest of this page. For real data, choose the bandwidth from what you know about the biology, such as the distance over which cells signal to one another, and from maps like these. mergeNiches() (merge_niches()) can pool several cell types into one niche group (all lymphocytes, say) before fitting. spiDE never tests an index type against its own niche, merged or not.

Fit the model

The fit takes the object with its niches, the bandwidth to use and, if we want to test a condition, the name of the condition column.

  • R
  • Python
fit <- fitSpiDE(spe, condition = "condition", sigma = 30, verbose = FALSE)
fit
#> SpiDEFit (slopes engine), bandwidth 30
#>   16 patients; condition: condition
#>   index A: 20 genes x 2 niches (B, C)
#>   index B: 20 genes x 2 niches (A, C)
#>   index C: 20 genes x 2 niches (A, B)
fit = sp.fit_spide(adata, condition="condition", sigma=30, verbose=False)
fit
#> SpiDEFit (slopes engine), bandwidth 30
#>   16 patients; condition: condition
#>   index A: 20 genes x 2 niches (B, C)
#>   index B: 20 genes x 2 niches (A, C)
#>   index C: 20 genes x 2 niches (A, B)

By default every cell type with at least min.cells cells in at least min.patients patients is an index type (min_cells and min_patients in Python), and every other cell type is tested as its niche. The index and niche arguments restrict this; niche types that are not tested stay in the model as adjustments. Genes detected in fewer than min.detect of an index type’s cells are not tested in it. The model adjusts for sequencing depth with the centred log library size of each cell, and further cell-level measurements such as cell area can be added with covariates. Python keeps R’s argument names in snake_case, so min.cells is min_cells.

The engine argument chooses how the error between patients is estimated. The default, "slopes", fits the model once without the condition and then estimates every patient’s own slope for every niche, each with a variance that allows for spatially correlated cells. Because the fit never sees the condition, any patient-level condition can be tested afterwards, and permuting the condition reruns only the test. The alternative, "sandwich", fits the condition-specific model directly, tests its coefficients with a patient-clustered sandwich standard error and needs the condition at fit time. The slopes engine is the more powerful of the two when effects vary between patients, and it is needed for spiGSEA(). The spiDE model explains both engines.

Test the slopes

The test combines the patients’ slopes. It always runs the pooled test, and it runs the condition-specific test when a condition is available, here the one recorded by the fit. A condition can also be given to testSpiDE() (test_spide()) directly.

  • R
  • Python
res <- testSpiDE(fit)
res
#> SpiDEResults (slopes engine)
#>   pooled across patients: 120 tests, 2 at FDR 0.05
#>   condition-specific (Responder - Non-responder; pooled_or_heterogeneity family): 2 tests, 1 at FDR 0.05
res = sp.test_spide(fit)
print(res)
#> SpiDEResults (slopes engine)
#>   pooled across patients: 120 tests, 2 at FDR 0.05
#>   condition-specific (Responder - Non-responder; pooled_or_heterogeneity family): 2 tests, 1 at FDR 0.05

The pooled test

The pooled results are a table with one row per triplet; results(res, test = "pooled") gives it in R and sp.results(res, test="pooled") in Python. estimate is the average within-patient slope on the natural-log scale per unit of the log1p niche density, t and p are the test statistic and its p-value, and q is the q-value after a Benjamini-Hochberg correction over every triplet.

  • R
  • Python
head(results(res, test = "pooled"))
sp.results(res, test="pooled").head()
#>   gene index niche  ... p.heterogeneity             q  in_family
#> 0   G1     A     B  ...        0.554557  8.234284e-09       True
#> 1   G9     A     B  ...        0.254027  1.676479e-03       True
#> 2   G8     B     C  ...        0.103677  5.685822e-02       True
#> 3  G18     A     B  ...        0.884934  2.443776e-01       True
#> 4   G2     A     B  ...        0.259633  4.198921e-01       True
#> 
#> [5 rows x 13 columns]

The planted triplet, G1 in A against B, comes out as the strongest pooled association, with a t of 6.83 in R. Remember that a pooled call says that, within a patient, index cells with more of the niche type around them express more (or less) of the gene, consistently across patients.

The condition-specific test

The condition-specific table has the same layout. Its estimate is the difference between the conditions in the average slope, the second level minus the first, and res$contrast (res.contrast) says which two levels were compared.

  • R
  • Python
res$contrast
#> [1] "Responder - Non-responder"
cond <- results(res, test = "condition")
cond[cond$in_family, ]
print(res.contrast)
#> Responder - Non-responder
cond = sp.results(res, test="condition")
cond[cond["in_family"]]
#>    gene index niche  ... p.heterogeneity         q  in_family
#> 1    G1     A     B  ...        0.554557  0.020112       True
#> 33   G9     A     B  ...        0.254027  0.272419       True
#> 
#> [2 rows x 13 columns]

By default the condition-specific test is carried out only among the triplets that pass the pooled test, or whose slopes vary between patients more than their sampling noise allows (p.heterogeneity, corrected at the same fdr). Neither filter looks at the condition, so the correction for multiple testing is spent on triplets that have something for the condition to explain, and the result is valid under any relabelling of the patients. Rows outside this family have q = NA (NaN in Python). Other families are available through the procedure argument: "heterogeneity" and "filtered" use one filter each, and "all" tests every triplet.

In the table, the planted slope is larger in responders than in non-responders by 0.27 log units per unit of log1p density in R (q = 0.02), which is the effect we planted. The whole pipeline can also be run in one call:

  • R
  • Python
res <- spiDE(toySpiDE, condition = "condition", sigma = 30)

spide() builds the niche matrix itself and does not keep it on the object (name= is the obsm prefix the niches are read from, or built into):

res2 = sp.spide(sp.datasets.toy_spide(), condition="condition", sigma=30, verbose=False)
print(res2)
#> SpiDEResults (slopes engine)
#>   pooled across patients: 120 tests, 2 at FDR 0.05
#>   condition-specific (Responder - Non-responder; pooled_or_heterogeneity family): 2 tests, 1 at FDR 0.05

Look at the patients behind a result

A call is only as good as the patients behind it. With the slopes engine, every patient has its own slope for every triplet, and these slopes are the evidence that the tests weigh. patientSlopes() (patient_slopes()) returns them as a table, with the slope’s variance and the number of cells that went into it.

  • R
  • Python
ps <- patientSlopes(fit, gene = "G1", index = "A", niche = "B")
head(ps[, c("patient", "condition", "slope", "var_spatial", "ncells")])

ps[["patient", "condition", "slope", "var_spatial", "ncells"]].head()

#> 0      S1      Responder  0.465072     0.008294      49

plotPatientSlopes() (pl.plot_patient_slopes()) draws them. Each point is a patient’s slope with its interval, sized by the weight the patient carries in the tests. The weighted average of each condition is marked, and the pooled estimate is shown as a band.

  • R
  • Python

plt.show()

For G1, the slopes of the patients lie mostly above zero in both conditions, which gives the pooled call, and the slopes of the responders sit further to the right than those of the non-responders, which is what the condition-specific test picks up. The panel title reports its difference and q-value. For G2, which has no planted effect, the slopes are spread widely on both sides of zero, their intervals are wide, and the two conditions overlap.

The model also gives each patient a baseline level of every gene, its intercept. These baselines absorb everything that differs between patients as a whole, so they are not tested, but they are worth a look. patientIntercepts() (patient_intercepts()) returns them with the patient-level covariates, and plotPatientEffects() (pl.plot_patient_effects()) summarises them by principal components of the intercepts, showing how much of each component each covariate explains.

In this example the first component of the intercepts lines up almost entirely with the condition, which is what we expect: the baselines absorb the difference in level between responders and non-responders, so that this difference cannot be mistaken for a difference in slope. Other covariates, such as the number of cells and the depth of a patient, explain smaller parts of the other components. If a slide or batch column lined up with a component of the slopes instead, the condition would be partly confounded with it, and that column should go into strata. Setting niche in the plot function draws the same plot for the slopes, which is the check to make before trusting a condition-specific call.

Test gene sets

Genes do not act alone, and a set of genes with a shared function often shows an effect that no single gene shows clearly. spiGSEA() (spi_gsea()) tests gene sets in the way the gene test tests genes. It takes the results and any named list (a dict in Python) of gene symbols, such as the collections of the msigdb package. Each patient gets a slope for the set, which averages its genes’ slopes after putting them on a common scale, and these set slopes go through the same pooled and condition-specific tests. By default (type = "competitive") the average over the other tested genes is subtracted, so a set is called when it moves more than the typical gene. It needs the slopes engine.

  • R
  • Python
sets <- list(planted = c("G1", "G2", "G3"), other = paste0("G", 4:8),
             rest = paste0("G", 9:20))
gs <- spiGSEA(res, sets, min.size = 3)
head(gs[, c("set", "index", "niche", "test", "size", "estimate", "p", "q", "q.global")])
sets = {
    "planted": ["G1", "G2", "G3"],
    "other": [f"G{i}" for i in range(4, 9)],
    "rest": [f"G{i}" for i in range(9, 21)],
}
gs = sp.spi_gsea(res, sets, min_size=3)
gs[["set", "index", "niche", "test", "size", "estimate", "p", "q", "q.global"]].head()
#>        set index niche    test  size  estimate         p         q  q.global
#> 0  planted     A     B  pooled     3  0.578673  0.000011  0.000032  0.000191

#> 2    other     B     C  pooled     5 -0.215171  0.048372  0.145115  0.233513

There are two q-values. q adjusts within each (index, niche, test) column, and q.global over every set, index and niche of a test. When there are many sets and many columns, q.global is the one to read. The heatmap shows the t statistic of every set in every (index, niche) column, with a dot where q.global passes.

The set holding the planted gene stands out in the column of A against B, where it is called, and no other set is called.

A different question: niche abundance

The tests above use only the slopes within patients. A patient whose index cells sit among many niche cells may also express a gene differently as a whole from a patient whose index cells do not. This is a real association, but it is a different claim. It says that patients with more of a niche type differ, not that a cell responds to its neighbours, and the patient intercepts absorb it so that the slope test never sees it. testNicheAbundance() (test_niche_abundance()) asks it directly. For each patient and index type it forms a pseudobulk profile and compares it with the patient’s average niche density, across patients.

  • R
  • Python
ab <- testNicheAbundance(spe, condition = "condition", sigma = 30, verbose = FALSE)
head(ab)
ab = sp.test_niche_abundance(adata, condition="condition", sigma=30, verbose=False)
ab.head()

#> 0   G1     A     B  niche  ...  3.140745             1  0.770461  0.945496
#> 1   G2     A     B  niche  ...  3.140745             1  0.770461  0.907598
#> 2   G3     A     B  niche  ...  3.140745             1  0.770461  0.662375
#> 3   G4     A     B  niche  ...  3.140745             1  0.770461  0.907598
#> 4   G5     A     B  niche  ...  3.140745             1  0.770461  0.737781
#> 
#> [5 rows x 12 columns]

With a condition, the rows with term "niche" give the association averaged over the two conditions, and the rows with "condition:niche" test whether it differs between them, again the second level minus the first. Each term is its own family for multiple testing, with its own q.global. A patient who alone carries most of a niche type’s spread is down-weighted (max.leverage, max_leverage in Python), so that one patient cannot make a call on its own. Gene sets go through the same test with the genesets argument.

The two kinds of result must not be mixed up, and never report a result of one test as a result of the other. A slope result says that, within a patient, cells with more of this niche differ, and an abundance result says that patients with more of this niche differ. plotNicheResponse() (pl.plot_niche_response()) shows both on one gene. With adjust = FALSE (adjust=False) it draws the raw data: each segment is one patient’s slope, the quantity spiDE tests, and the dashed line through the patients’ means is the between-patient association that the abundance test tests.

  • R
  • Python
plotNicheResponse(spe, res, gene = "G1", index = "A", niche = "B", adjust = FALSE)
fig = sp.pl.plot_niche_response(adata, res, gene="G1", index="A", niche="B", adjust=False)
plt.show()

Within a patient the segments rise with the density of B, more steeply for some patients than for others, while the dashed line across the patients’ means is the different, between-patient question.

Plots

All the plots are in one house style with one colour-blind-safe palette (theme_spiDE() and spiDEColours() in R, pl.style() and pl.spide_colours() in Python) that uses one pair of colours for slopes that rise or fall with the niche and another pair for the two levels of the condition. In R every plot is a ggplot2 object that returns its data in p$data, so a plot is changed by adding layers or a theme, and any two plots can be combined with patchwork. In Python every plot is a matplotlib Figure.

Where the calls are

plotCallMap() (pl.plot_call_map()) counts, for each (index, niche) column, how many triplets pass, separately for slopes that rise and slopes that fall with the niche’s density, and plotTopTriplets() (pl.plot_top_triplets()) shows the strongest ones. When we give it the data object, a triangle marks a gene that is several-fold higher in the niche type than in the index type, which we come back to below.

  • R
  • Python
plotCallMap(res, test = "pooled")
plotTopTriplets(res, test = "pooled", n = 12, spe = spe)
fig = sp.pl.plot_call_map(res, test="pooled")
plt.show()
fig = sp.pl.plot_top_triplets(res, test="pooled", n=12, adata=adata)
plt.show()

Two triplets pass, both in the column of index type A against niche type B, where the effect was planted: the planted gene G1, whose slope rises, and G9, whose slope falls. G9 has no planted effect, so it is an unplanted call at the default threshold, which is what we should expect to see now and then among 120 triplets.

The cells behind a slope

plotNicheResponse() shows the cells themselves. By default, each patient’s fitted intercept is divided out, so the patients share one level and the slopes that the tests compare are easy to see.

For G1, the expression of the responders’ cells rises with the density of B while that of the non-responders is nearly flat. For G2, there is no clear trend in either group.

Check for spillover

Cell segmentation is never perfect, and transcripts of a neighbouring niche cell can be assigned to an index cell. These transcripts rise with the niche’s density and look like a response of the index cell. plotSpillover() (pl.plot_spillover()) plots every triplet by its signed z statistic against how much higher the gene is in the niche type than in the index type, and marks the region of genes that are several-fold higher in the niche type. If the calls fell mostly in that region, they would be the niche type’s own markers and spillover the likely explanation.

  • R
  • Python
plotSpillover(res, spe)
fig = sp.pl.plot_spillover(res, adata)
plt.show()

In this example none of the calls lies in that region, so spillover does not explain them. In real data, report the niche type’s fold change together with every call.

Practicalities

Runtime. The fit is the expensive step. Every gene is fitted separately in every index type, so the time grows with the number of index types, the number of genes and the number of cells, but it hardly depends on the number of patients, because the patient baselines are handled algebraically. The example above takes a few seconds. Testing is fast, and a permutation of the condition under the slopes engine reruns only the test.

Parallelism. Genes are fitted independently within an index type, so they can be spread over workers: with the BPPARAM argument in R and n_jobs in Python. Results are identical for any n_jobs.

  • R
  • Python
library(BiocParallel)
fit <- fitSpiDE(spe, condition = "condition", sigma = 30,
                BPPARAM = MulticoreParam(4))
fit = sp.fit_spide(adata, condition="condition", sigma=30, n_jobs=4)

Forked workers in R run one BLAS thread each when the RhpcBLASctl package is installed. Otherwise, set OMP_NUM_THREADS=1 in the job, because workers that each use many threads compete with one another and run much slower.

Counts and sparsity. Counts must be integers, and a back-transformed normalised layer is refused. In Python layers["counts"] can be a CSR or CSC sparse matrix and gives the same results as dense.

Several bandwidths. One fit uses one bandwidth. We can build the niches at several bandwidths and fit each one, but the results are a sensitivity analysis and not a search: each bandwidth is its own set of tests, and picking the best of them after looking would not be valid. Calls that hold at both bandwidths are the more convincing. Below we refit index type A at the smaller bandwidth and count the pooled calls at each bandwidth.

  • R
  • Python
fit10 <- fitSpiDE(spe2, condition = "condition", sigma = 10, index = "A",
                  verbose = FALSE)
res10 <- testSpiDE(fit10)
r10 <- results(res10, test = "pooled")
r30 <- results(res, test = "pooled")
r30 <- r30[r30$index == "A", ]
c(sigma10 = sum(r10$q < 0.05, na.rm = TRUE), sigma30 = sum(r30$q < 0.05, na.rm = TRUE))
#> sigma10 sigma30 
#>       3       2
fit10 = sp.fit_spide(adata10, condition="condition", sigma=10, index="A", verbose=False)
r10 = sp.results(sp.test_spide(fit10), test="pooled")
r30 = sp.results(res, test="pooled")

#> {'sigma10': 3, 'sigma30': 2}

Both bandwidths call a handful of triplets in A, including the planted one, so the conclusion does not hinge on the choice here.

Do R and Python agree?

spidepy is a port of the R package, and a test suite compares it with reference values computed by R, but the two are separate implementations, so we do not take agreement for granted. Here we compare the tables that the two have just produced on the same data: the pooled and condition-specific slope tests, the gene-set test and the niche-abundance test.

as_r_table <- function(code) {
  d <- reticulate::py_to_r(reticulate::py_eval(code, convert = FALSE))
  as.data.frame(lapply(d, unlist), stringsAsFactors = FALSE)
}
key <- function(d) paste(d$gene, d$index, d$niche, d$term, d$set, d$test)
cmp <- function(r, p, col) {
  p <- p[match(key(r), key(p)), ]
  c(max_abs_diff = max(abs(r[[col]] - p[[col]]), na.rm = TRUE),
    max_rel_diff = max(abs(r[[col]] - p[[col]]) / pmax(abs(r[[col]]), 1e-8), na.rm = TRUE))
}
r_pooled <- results(res, test = "pooled")
r_cond <- results(res, test = "condition")
py_pooled <- as_r_table("sp.results(res, test='pooled').to_dict('list')")
py_cond <- as_r_table("sp.results(res, test='condition').to_dict('list')")
py_gs <- as_r_table("gs.to_dict('list')")
py_ab <- as_r_table("ab.to_dict('list')")
out <- rbind(pooled_estimate = cmp(r_pooled, py_pooled, "estimate"),
             pooled_t = cmp(r_pooled, py_pooled, "t"),
             condition_estimate = cmp(r_cond, py_cond, "estimate"),
             gene_set_estimate = cmp(as.data.frame(gs), py_gs, "estimate"),
             abundance_estimate = cmp(as.data.frame(ab), py_ab, "estimate"))
signif(out, 2)
#>                    max_abs_diff max_rel_diff
#> pooled_estimate         1.2e-15      1.5e-14
#> pooled_t                1.2e-14      1.5e-14
#> condition_estimate      2.9e-15      1.7e-14
#> gene_set_estimate       2.4e-15      2.1e-14
#> abundance_estimate      9.7e-14      6.5e-12
calls <- function(d) sort(key(d)[which(d$q < 0.05)])
c(pooled_calls_R = length(calls(r_pooled)), pooled_calls_Python = length(calls(py_pooled)),
  same_pooled_calls = identical(calls(r_pooled), calls(py_pooled)),
  same_condition_family = identical(r_cond$in_family, py_cond$in_family[match(key(r_cond), key(py_cond))]))
#>        pooled_calls_R   pooled_calls_Python     same_pooled_calls 
#>                     2                     2                     1 
#> same_condition_family 
#>                     1

Each row of the table gives the largest absolute and relative difference over all rows between the R and the Python value. On this data they are at the level of floating-point rounding, and the two languages call the same triplets. This is a statement about this example. Real data are larger, the optimisers see more difficult genes, and small differences in the dispersion estimates can reach the last reported digits, so when you compare the two on your own data, compare calls and effect sizes, not digits.
