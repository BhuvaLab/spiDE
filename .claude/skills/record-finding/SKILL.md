# Record a finding

The package's discipline (CLAUDE.md, "Where the evidence lives") is that
every non-obvious default was chosen on measurement and the measurement is
written down. That decays when a number lands in one place and not the
others, or is written without the run that produced it, and the
`evidence-auditor` agent then finds the drift months later. This skill
writes the same finding to each location once, in that location's voice.

## 1. Collect the provenance first

Refuse to write a number without all of these; ask for the missing one.

| item | where it comes from |
|---|---|
| date | today, absolute (YYYY-MM-DD), never "yesterday" |
| job ids | `sacct -u $USER -S <date> -X --format=JobID,JobName,State` |
| package snapshot | `SNAPSHOT_PROVENANCE.txt` in `$SPIDE_PKG` (branch, HEAD, uncommitted diff); "live tree" is a defect to record, not a provenance |
| seed | what the driver wrote alongside the output (`spide_pkg`, `backend`, seed) |
| the arm's settings | `random`, `df.method`, `dispersion`, `psi`, `combine`, bandwidths, `S`, reps |
| the canonical table it lives in | `research/reports/benchmarks/tables/<scenario>.rds`, with the `method`/`design` row it added |
| what it is compared with | the arm or the prior measurement it is being read against |

A count of discoveries additionally needs the `calibration-check` skill's
output; do not record a count that has not been through it.

## 2. Decide the claim

Write one sentence: what was measured, on what, and what it decides. Be
exact about what it does **not** show. The record is full of numbers that
were later found to be circular (the 6x gene filter, scored on its own grid),
measured on a predecessor estimator, or read from a summary table that could
not distinguish two hypotheses (null type-I at S = 4 looked fine while FDP
was 0.35). If the finding has a caveat of that kind, the caveat goes in every
location, not only the long one.

## 3. Write to each location

Read the existing text around the insertion point in each file first; match
its voice and do not repeat what it already says.

**`research/fdr-ordering/FINDINGS.md`** (or the study's own findings file
under `research/<study>/`): the long form. A dated `##` heading, the
question, the setup with the full provenance table, the numbers as a table,
the interpretation, and a "what this does not show" line. This is the only
place the raw numbers need to appear in full. Committed in the research
submodule, so the package's submodule pointer must move afterwards.

**`NEWS.md`**: only if the finding changes a user-visible default, argument
or behaviour. One bullet under the current version's `## Changes`, in the
existing style (bold lead sentence, the deciding number, the arm name), with
a pointer to the report or findings entry.

**`CLAUDE.md`**: only if the finding changes how future work should be done
(a default, a warning, a measured cost, a refuted hypothesis). Put it in the
section it belongs to, dated in parentheses as the others are, and if it
supersedes an earlier statement, edit that statement rather than adding a
contradiction below it. Refuted hypotheses go into the list of things not to
re-run.

**Memory** (`/home/uqdbhuva/.claude/projects/-scratch-project-mnt-S0249-R-projects-spiDE/memory/`):
one file with the frontmatter the memory system expects (`name`,
`description`, `metadata.type: project`), the fact, **Why** and **How to
apply** lines, links to related memories, and a one-line pointer added to
`MEMORY.md`. Update an existing memory that covers the same question instead
of adding a second.

**The report**, if a benchmark report reads the table: check every one-row
lookup in `research/reports/benchmarks/*.Rmd` that reads the affected
scenario table still returns one row with the new arm present (a second
`design` arm broke the GSEA report's `gv()` on 2026-09-08). Rebuild the
sites with the `build-site` skill.

## 4. Check before you stop

- The same number appears in every location it was written to, with the
  same units and the same caveat.
- The canonical table was regenerated by its installer
  (`research/R/install_results.R`, `research/plasmode/install_twostage.R`),
  never written directly; a hook blocks the direct write.
- `vignettes/spiDE-calibration.Rmd` is still the only vignette quoting
  benchmark numbers; the finding is not pasted into another vignette.
- Run the `evidence-auditor` agent on the edited files when the finding
  changes or supersedes a quoted number.
