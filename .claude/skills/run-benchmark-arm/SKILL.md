# Run a benchmark arm

Every rule here exists because its absence cost a run on this project. Follow
them in order; each step is cheap next to the multi-hour job it protects.

## 1. Freeze the package

```bash
SNAP=$(.claude/skills/run-benchmark-arm/scripts/freeze_snapshot.sh <label>)
```

Pass `SPIDE_PKG=$SNAP` to every task. SLURM tasks `load_all()` the live tree at
*task start*, so array tasks starting at different times pick up different code
if you edit while a run is in flight. That has corrupted 94 in-flight tasks on
this project. The snapshot records branch, HEAD, and the uncommitted diff in
`SNAPSHOT_PROVENANCE.txt`, so a result can always be traced to the exact code.

## 2. Seed, and record the seed

`SpaNorm::fitNB()` subsamples cells for dispersion above a size threshold and
sets **no seed internally** (measured: identical at 60 cells; two identical
calls differ by max|d psi| = 0.245 at 600 cells). Any run whose numbers will be
cited must `set.seed()` — derive it from the array index so tasks stay
independent — and write it into the output alongside `spide_pkg`, `backend` and
the estimator settings. Without this, a re-run does not reproduce its own
numbers.

## 3. Size from measurement, not from fear

Check `sstat -j <jobid> --format=MaxRSS` on the *same code path*, then add ~3x.
Over-requesting is not free insurance: the account QOS caps mean it throttles
your own concurrency. Measured 2026-08-13: a real-cohort run peaked at 21.7 GB
against a 220 GB request, and three 24-core jobs saturated `QOSGrpCpuLimit` at
80 CPUs, blocking a 2-core diagnostic needed to debug one of them. See the
`hpc-job-sizing` skill for the full decision procedure.

## 4. Write atomically, and resume

Write each part to `<path>.tmp$$` then `mv` into place, so a job killed
mid-write leaves the previous part intact rather than a truncated file. On
restart, load existing parts and skip completed reps — but carry the PRIOR
list forward rather than rebuilding it, or the resume silently drops earlier
replicates.

## 5. Rows, not new files

A new method arm is extra **rows** in the one canonical table per scenario
(`method` / `df.method` / `stage1` / `ls.model` columns), never a parallel file
that would carry a stale copy of the other arms. The canonical tables are
regenerated by `research/R/install_results.R` and
`research/plasmode/install_twostage.R`; a hook blocks direct writes to them.

## 6. Gate anything GPU

GPU work needs h100 — a100 fails fp64 `digamma` inside NB dispersion *mid-run*,
and l40s runs fp64 at ~1:64. Gate the real run behind a verification job with
`--dependency=afterok`, and make sure the gate cannot pass vacuously: a gate
that `source()`d a script ending in `quit()` "passed" in 68 seconds having
tested nothing beyond its first layer. Set a flag per layer and assert all of
them at the end. Also check `squeue -h -j <id> -o %S` before promising a
turnaround — h100 is frequently saturated for many hours.

## 7. Score before quoting

Run the `calibration-check` skill on the output before reporting any discovery
count. A table with `sd(t) > 1.2` produces q-values that do not mean what they
say — on YTMA the unrestricted table called ~40% of a 13,348-gene panel
significant.
