# Diagnostic and interpretation plots for spiDE

Date: 2026-10-01. Branch: `feature/plots` (worktree `../spiDE-plots`, from `main` at fa18084).
Status: design agreed in conversation; prototypes rendered on GSE250346 (release study,
spiDE 0.99.32) and reviewed; this spec awaits approval.

## Purpose

spiDE ships no plots. Users rebuild the same few figures by hand (the YTMA v12 report has
six ad-hoc ones), and the vignette's only figure is an inline `ggplot()` chunk. This adds a
small plotting layer that:

- covers the questions a user has at each step, from the niche covariate to the calls,
  with one function per question and a stated reason for each;
- gives publication-grade figures by default, so that little editing is needed before a
  paper;
- is easy to modify: every function returns one ggplot whose data is the documented
  `p$data`, so a user adds layers or re-plots rather than editing package code, and
  patchwork composes any two of them.

## Decisions (from the conversation)

- ggplot2 only; one ggplot per function (facets allowed, no internal patchwork).
- The house style is `vissE::bhuvad_theme()`: `theme_minimal()` with a black panel border,
  no grid, text scaled by `rl`, boxed strips, italic legend titles; plus black axis ticks.
- No titles or captions by default (the figure legend carries them in a paper); every
  encoding has a legend key; gene symbols are italic (plotmath).
- One colour per role, the same in every plot, validated for colour blindness (all pairs,
  including across roles, with the dataviz validator):

  | role | colours |
  |---|---|
  | direction (up / down), diverging t | amber `#B8791A` / violet `#5B4B9A`, neutral `#F7F7F7` midpoint |
  | condition (first level / second) | teal `#0A9396` / rufous `#AE2012` (coolors palette `001219-005f73-0a9396-94d2bd-e9d8a6-ee9b00-ca6702-bb3e03-ae2012-9b2226`) |
  | magnitude (density, R², bars) | scico `lapaz` (Crameri), light to dark; its hex values written into the package (no dependency); points on white start at its sand end |
  | a nuisance factor (slide, batch) | Okabe-Ito up to 8 levels, else hue |
  | marks, context, non-calls | black; greys |

  Red/blue was rejected for direction (hot/cold, stop/go); sky/teal for the condition (too
  close); teal/magenta collapses under deuteranopia.
- `plotCallMap()` defaults to the heatmap: at 5 cell types every pooled pair had calls and
  the graph was a hairball; the graph stays as `style = "graph"`, where it reads well for
  sparse (condition) calls.
- Several genes in `plotPatientSlopes()` / `plotNicheResponse()` are faceted by gene.
- `plotNicheResponse(adjust = TRUE)` divides out each patient's fitted intercept (not the
  patient's own mean: patients sit at different mean densities, so centring on their own
  means offsets parallel lines; the intercepts are at a common reference density).
- A study of what the patient intercepts absorb (patient-level nuisance), and of the same
  covariates on the slopes, where nuisance can reach the tests.

## The functions

Argument names follow the package (dot-separated, `min.cells` style). `x` is a
`SpiDEResults` unless stated. Every function validates its inputs with checkers in
`R/checkers.R`, refuses legacy objects (`.assertCurrent()`), and documents the columns of
`p$data`.

| function | shows | what the user sees | needs |
|---|---|---|---|
| `plotNicheMap(spe, niche, sample, index = NULL, sigma = NULL, section = NULL, ...)` | one section, cells coloured by log1p density of `niche`; with `index`, only index cells coloured, others light grey; scale bar | whether the bandwidth is sensible (speckled = too small; flat within a section = absorbed by the intercept); where index cells sit | spe |
| `plotPatientSlopes(x, gene, index, niche, ci = 0.95)` | per patient: slope and CI from the variance the test uses (`v_model x factor`), point size = weight in the test; pooled estimate and CI as a band; condition rows with each group's weighted mean; strip: gene, slope difference and q | whether a call rests on agreeing patients or a few heavy ones; why a condition test is NA (< 3 effective patients per group) | slopes engine |
| `plotNicheResponse(spe, x, gene, index, niche, adjust = TRUE, bins = 8)` | index cells' expression (CP10k, log axis) against log1p niche density, binned. `adjust = TRUE`: patients' intercepts divided out; faint per-patient bin means, mean across patients per bin with 95% CI, each group's fitted slope (dashed). `adjust = FALSE`: each patient's within-patient slope through its centroid, patient centroids, and the between-patient line through them | the data behind a slope; linearity on log1p; the tested (within) vs the absorbed (between, `testNicheAbundance()`'s question) association | spe; intercepts (0.99.33 fit) for `adjust = TRUE`; per-patient lines need the slopes engine (sandwich: the pooled line) |
| `plotCallMap(x, test = NULL, fdr = x$fdr, style = c("heatmap", "graph"), min.calls = 1)` | calls per (index, niche), faceted up / down (pooled: "rises / falls with density"; condition: "steeper in <level>"). Heatmap: counts in tiles, grey = not tested. Graph: cell types on a fixed circle, niche -> index arrows, width = genes | where the signal is; one-sided pairs (the spillover shape) | - |
| `plotTopTriplets(x, test = NULL, n = 30, gene = NULL, index = NULL, niche = NULL, spe = NULL, fold = 4)` | forest: estimate and t-based 95% CI, faded where q > fdr; filter by gene / index / niche then rank; with `spe`, hollow triangles for genes >= `fold`-fold higher in the niche type | effect sizes and uncertainty of the strongest calls or of the user's genes; which look like spillover | spe for the marker flag |
| `plotSpillover(x, spe, test = "pooled", fold = 4, label = 6)` | every tested triplet: log2(expression in niche type / in index type) against signed z; calls coloured by direction; shaded region >= `fold`; count of calls in it; top markers labelled | whether the calls concentrate among niche-type markers rising with density (seen on all five release cohorts) | spe |
| `plotTripletHeatmap(x, features = NULL, test = NULL, n = 30, limit = NULL, cluster = TRUE)` | features x (index facet, niche) tiles of t (diverging), dot where q <= fdr, grey where not tested; rows clustered. `x` is a `SpiDEResults` (genes, italic) or a `spiGSEA()` table (sets, `q.global`) | a gene's or pathway's niche-response profile across all pairs | - |
| `plotPValues(x)` | p-value histograms, test x expression fifth (within index type), uniform level dashed | a sanity check: a hump at 1 (low power), excess near 0 only in bright genes (the known failure shape); not a calibration test (the Rd says so and points to the calibration vignette) | - |
| `plotPatientEffects(x, index, niche = NULL, covariates = NULL, type = c("association", "pca"), colour.by = NULL, n.pcs = 5, ntop = 500)` | PCs of the patients' gene-centred intercepts (or, with `niche`, of their slopes scaled per gene as in `spiGSEA()`) against patient covariates: adjusted R² tiles; covariates = every patient-constant colData column plus derived (log10 cells, mean log depth, mean log1p density of each niche); `type = "pca"`: PC1 x PC2 coloured by one covariate | what the intercepts absorb (condition main effect, composition, batch: harmless to the tests by design) and whether the same covariates structure the slopes (not harmless: the case for `strata`) | intercepts (0.99.33 fit); slopes engine for `niche` |

Plus:

- `patientIntercepts(object, gene = NULL, index = NULL)`: long form, like
  `patientSlopes()`, both engines, for users' own models of the intercepts.
- `theme_spiDE(rl = 1.1)` and `spiDEColours(role = NULL, n = 9)` exported, so users' own
  figures match.

Considered and left out: volcano (slopes of different niche types are on different scales;
plots 4 and 5 carry its content); QQ plot (the histogram shows the conservative hump); a
null-calibration plot (needs block nulls the package does not generate; revisit if it
does); a patient-weight heatmap (plot 2 shows weights per triplet); a niche-abundance map
and cell-type maps (plot 3 shows the abundance association; cell-type maps are not
spiDE-specific).

## What the fit must keep (the one change outside the plotting layer)

`fitSpiDE()` already estimates each patient's intercept per gene in the shared,
condition-free fit (`fit0$alpha[, des0$intercept_cols]`) and discards it. Each element of
`SpiDEFit@index` gains, for both engines:

- `intercept`: genes x patients, the shared fit's patient intercepts (under
  `depth = "spatial_spline"`, the intercept column of each patient's block);
- `niche_mean`: patients x tested niches, the mean log1p density of the patient's index
  cells;
- `loglib_mean`: per patient, the mean log library size of its index cells.

Sizes are genes x patients, like `pooled`. The slopes engine's fit still never sees the
condition. A fit without these (<= 0.99.32) works in every plot except `plotNicheResponse(adjust
= TRUE)` and `plotPatientEffects()`, which stop with a message to refit. The prototype
refit reproduced the stored pooled slopes of all five GSE250346 index types to <= 2.6e-15,
so the stored intercepts are exactly what `fitSpiDE()` computes. The `SpiDEFit-class` Rd and
`show()` stay otherwise unchanged.

## Internals

- `R/plot-theme.R`: palette constants, `theme_spiDE()`, `spiDEColours()`, the internal
  scales (`.scaleDirection()`, `.scaleCondition()`, `.scaleMagnitude()`, `.scaleT()`), and
  plotmath helpers (`.itGene()`, `.itTriplet()`).
- `R/plot-helpers.R`: shared data builders: `.slopeWeights()` (v_model x factor and the
  DerSimonian-Laird tau2 over the whole gene family of a column, as the test computes it:
  invariant 2), `.expressionBands()`, `.cellTypeMeans()` (genes x cell types CP10k by a
  sparse product; counts never densified whole: invariant 5; merged niche columns resolved
  through `metadata(spe)$spiDE_niche_groups`), `.nicheFold()`, `.indexCellData()` (one
  gene set's rows over one index type's cells).
- One file per plot family: `R/plot-niche.R` (map, response), `R/plot-patients.R`
  (slopes, effects), `R/plot-results.R` (call map, top triplets, heatmap, p-values,
  spillover).
- Plain exported functions, not S4 generics (simpler to read and extend; the dispatch on
  `SpiDEResults` vs `spiGSEA()` table is one `if`).
- Dependencies: ggplot2 and scales move to Imports; ggrepel in Suggests (fallback:
  `geom_text(check_overlap = TRUE)`); patchwork in Suggests for the vignette.

## Testing

`tests/testthat/test-plots.R` on `toySpiDE` (both engines, with and without a condition):
each plot builds (`ggplot_build()` without error or warning), `p$data` has the documented
columns, errors are informative (sandwich engine for the slopes-only views; a fit without
intercepts; unknown gene/index/niche). Specific checks: the stored intercepts equal a direct
`.fitIndexGLM()` refit's; weights sum to 1 per gene in `plotPatientSlopes()`; the niche fold
of a merged niche uses its members' cells; `plotPatientEffects()` finds the planted
condition in the toy's intercepts. No image snapshots (fragile across ggplot2 versions);
every plot is rendered and looked at on the toy and on GSE250346 before review.
